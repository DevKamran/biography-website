# Portfolio Monorepo

Personal portfolio site (Next.js) with an AI chat widget that answers visitor
questions about the site owner. Chat answers are generated by a
retrieval-augmented-generation (RAG) API that reads the owner's actual resume
— not hand-maintained Q&A data.

## How it fits together

1. Visitor opens the chat widget → frontend calls `POST /api/resume-query`
   with the visitor's question.
2. That route proxies the question to the `apps/agent` FastAPI service
   (`RESUME_RAG_API_URL`, default `http://localhost:8000`).
3. `apps/agent` embeds the question, retrieves the closest resume chunks from
   Qdrant, and asks Gemini to answer strictly from those chunks — if the
   answer isn't in the resume, it says so instead of inventing details.
4. The frontend renders the reply in the chat widget.

> **Note:** `app/api/livekit-token/route.ts` and `lib/use-livekit-chat.ts`
> are leftover from an earlier LiveKit-based chat design. There is no
> LiveKit worker process in this repo to answer dispatched rooms, so that
> path is currently non-functional — the resume-query path above is what
> actually powers the chat widget today.

## Prerequisites

- Node.js ≥ 18.18
- Python ≥ 3.9
- A free [Google AI Studio](https://aistudio.google.com/apikey) key (Gemini)
- A free [Qdrant Cloud](https://cloud.qdrant.io) cluster

## Setup

### 1. Frontend

```bash
cd apps/web
cp .env.local.example .env.local   # fill in RESUME_RAG_API_URL (and LiveKit vars, unused for now)
npm install
npm run dev
```

Runs at http://localhost:3000.

### 2. Resume RAG API

```bash
cd apps/agent
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env               # fill in GEMINI_API_KEY, QDRANT_URL, QDRANT_API_KEY
python ingest.py --file data/KamranAli_Resume.pdf --document "KamranAli_Resume"
uvicorn main:app --reload --port 8000
```

Both apps must be running for the chat widget to work — the frontend serves
the site and proxies chat requests, the agent API is what actually answers
them.

## Filling in your content

- `apps/web/lib/portfolio-data.ts` — powers the visible page sections (hero,
  skills, projects, experience)
- `apps/agent/data/KamranAli_Resume.pdf` — replace with your own resume (`.md`
  or `.pdf`), then re-run `ingest.py` so the chat agent's answers stay in
  sync with what's on the page

## Deployment

- **Frontend**: Vercel (or any Next.js host).
- **Agent**: `apps/agent` ships a `Dockerfile` — deploy to Render, Railway,
  Fly.io, or a small VPS as a long-running container. After deploying, run
  `ingest.py` once (locally against the same Qdrant cluster, or as a
  one-off job) — the container's default `CMD` only starts the API server,
  it does not ingest automatically.
- Set `RESUME_RAG_API_URL` on the frontend to the deployed agent's URL.
